# Four-arm native decision memory comparison



This optional outer driver composes the existing native ticket TRAIN runner,

consented decision-evidence store and ticket dispatcher. It compares bounded

frozen context, retrieval-only, adapter-only and hybrid memory. It adds no learner

framework or objective. The original native workflow defaults remain unchanged.



## Information and chronology



Exactly two passes of the existing twelve correct TRAIN demonstrations produce

24 delayed-label native updates before any development episode. Original inbox

observations explicitly permit training and evidence reuse. Evidence records bind

the actual observation, label-arrival, application, request, target, policy and

consent. Cutoff48 follows observations0..46 and labels/applications1..47. Final,

probe and development labels cannot enter training or the store.



One fit supplies owned source0/24 snapshots shared by all arms:



| Arm | Selected native state | Decision path |

|---|---|---|

| frozen_context | source0 | actual native output with bounded JSON evidence |

| retrieval_only | no native readout | deterministic nearest eligible TRAIN label |

| adapter_only | source24 | actual native output without evidence |

| hybrid | source24 | actual native output with the same JSON evidence |



The store has24 original additions, zero label edits, top1 retrieval, at most768

UTF-8 context bytes and32KiB canonical storage. The separately accepted editable

case establishes causal revision behavior; no original TRAIN receipt is edited

here. Instructions and candidate definitions remain outside the editable query.

This is protected wire structure, not semantic prompt-injection immunity.



Each arm executes ordinary invoice, stale-once parcel and revoked-commit invoice,

at most six decisions each. The same ex-ante cases can expose different faults

and costs because policies take different actions. All arms have the same task

TRAIN information; they differ in optimization, repeated exposure, capacity and

computation. Released-base pretraining exposure is unknown. This is not matched

compute or an unseen-task generalization study.



## Local execution and boundaries



The model/checkpoint must already be cached in the existing qualified WSL native

environment. No download, installation, external tool action or final evaluation

is part of this driver. Follow the frozen local protocol and source/software/

executor gates before any native invocation:



```powershell

.venv/Scripts/python.exe -X utf8 -B artifacts/runs/native-memory-comparison-20261022/qualify.py

.venv/Scripts/python.exe -X utf8 -B artifacts/runs/native-memory-comparison-20261022/execute.py

```



These stage commands create fresh one-shot receipts and refuse existing outputs.

They are evidence commands, not permission to rerun the spent experiment. A

future independent case requires its own prospective allowance and frozen inputs.

The script interface is `python -B -m scripts.run_open_jev_memory_comparison

--source PATH --checkpoint PATH --output FRESH_JSON` in that native environment.



The finite aggregate prediction limit binds before the first readout and cannot

be enlarged by constructing another wrapper. Restoring snapshots never refunds

training/readout work. The existing runner validates preceding receipts before

more work and releases owned snapshots even on failure. Evidence construction

pre-admits all receipt bindings and retains any paid add prefix after failure.

## Executed bounded result (2026-10-22)

Independent ACTUAL review accepted the original bounded R5.7 comparison criterion
using this four-arm study plus the separately accepted editable-evidence case.
Frozen context, retrieval-only and hybrid each completed ordinary invoice and
stale parcel recovery, then safely refused the revoked commit. Adapter-only
completed invoice but again committed the wrong parcel workflow. Raw successes
are2/3,2/3,1/3,2/3; every arm has one safe denial. Retrieval-only achieves the same
successful endpoints without native readout; no hybrid advantage is established.

makes11 readouts; context consumes6,950 tokens per arm versus adapter3,010.

resident, so this is not isolated process memory or matched-compute evidence.

and ignored-linear-context results remain preserved.
