# From-birth private adaptation and returning-context games

An installed wheel exposes the same options through `circadian-affine-game`:

```text
circadian-affine-game --example-affine-adaptation --all-old-tasks --describe
circadian-affine-game --example-affine-adaptation --all-old-tasks --output matched-all-old.json
```

The wheel includes this guide under `share/doc/circadian-predictive-coding/`.
Description is metadata only and needs the NumPy base dependency. Actual learning
and gameplay require the pinned MiniGrid extra, a new output file and an explicit
local execution budget. Package installation does not renew any spent experiment
allowance or establish native task success. The all-old roster and original
matched controls below are unchanged.

The explicit terminal joint-only mode uses the existing stronger affine control:

```powershell
python -m scripts.run_minigrid_linear_fit_control --example-affine-adaptation --heldout-joint --describe
python -m scripts.run_minigrid_linear_fit_control --example-affine-adaptation --heldout-joint --output joint-heldout.json
```

This mode pays the fresh source's six fits/108 row exposures, then only the
fixed `joint_ABC_F` arm's two fits/72 row exposures. The actual endpoint has
eight fits/180 exposures and two36-row heads. It plays only D blue/red with
FINAL roles, seed17 and max16 steps, through the existing read-only kernel.
There are no F-only fits, repeated known-task games or fits after final access.
The API option is `run_workflow(private_adaptation=True, joint_heldout=True)`;
it cannot combine with other adaptation modifiers. The original default
comparison and historical ordinary10/252 held-out admission remain available.

Why this: the joint control was selected from known TRAIN results before D
access. Its paid endpoint and returned results are pinned around boundary
callbacks; corruption refuses completion while preserving paid observations.
D is excluded from this model's fits but globally seen in repository development.
This mode does not establish untouched statistical generalization or authorize
tuning, selection or promotion from final outcomes. See the
[scoped evidence](reports/affine-joint-heldout-20261031.md).

The earlier installed qualification is **incomplete**: that run finished all
ten fits and both private comparisons, then reached its declared work deadline
after five of eight native games. The failed attempt and partial report are
preserved; no automatic retry is authorized by the recorded protocol.

With the existing pinned MiniGrid optional requirements available:

```powershell
python -m scripts.run_minigrid_linear_fit_control --example-affine-adaptation --describe
python -m scripts.run_minigrid_linear_fit_control --example-affine-adaptation --output private-adaptation.json
# Installed equivalent: circadian-affine-game with the same arguments.
```

Output must be new. Failure retains the observed report and exits nonzero.
Describe performs no data lookup, learning or gameplay. The native runtime is
checked before TRAIN data or learners are created. No historical run JSON,
pretrained parameters, Torch or GPU is required. The normal `--example-affine-play`
command keeps its existing behavior.

The existing delayed stream starts from unfitted affine heads and fits bundled
TRAIN A/B/C blue/red sources: six updates, 108 row exposures, including 54 replay
exposures. Its actual complete six-receipt endpoint becomes the frozen reference.
The optional outer deadline is checked between absolute update boundaries without
restarting the stream, changing delay-one receipts or renewing its budget.

The original F collector runs four closed teacher episodes, seed 17, at most 16
steps each. The original complete 16 probe-train plus two probe-test packet release
is validated before selecting its fixed first two training packets. These selected
raw episodes retain their roles and provenance. Probe-test labels are readouts
only; they never enter training, replay selection, promotion or the TRAIN bank.
Final evaluation remains unavailable.

Both existing private controls start from the same current-run reference. Each
performs two 36-row fits. `current_only` repeats F, paying 72 F exposures, including
54 extras. `joint_ABC_F` pays 18 F plus 54 old TRAIN exposures. Admission attempts
remain permanent charges even if the solver fails; committed replay is separately
reported. Each private endpoint has eight native fits and 180 native row exposures.
The overall run pays ten fits and 252 rows; no historical study-arm costs are
invented for this fresh lineage. The original historical commands retain their
original provenance metadata and authority.

The existing native evaluator then plays F blue/red followed by returning A
blue/red for **both** private models. Returning A is the original named preset A:
branch row 3, rotation 0, grey walls, no swap. All seven native actions remain legal,
with raw first argmax, seed 17 and a maximum of 16 decisions per game. No private
model is selected or promoted. Complete negative games are valid results.

One whole-workflow supervisor reserves capture time at 170 seconds, with a
180-second ceiling and 512 MiB sampled process RSS. Existing TRAIN/private/readout
authorities keep their separate ceilings and original clocks. Each preceding
paid phase is checked before more work; changed values or equal container
replacements are refused. Failed collection cleanup and partial games remain in
the bounded report, with attempted phase names distinguishing unreturned work
from work never started. No budget or sunk charge is refunded.

Why this composition: accepted experiments already demonstrate the fixed task
behavior. Reusing their original components makes it runnable from birth without
adding an optimizer, source loader, replay policy or orchestration framework.
This is fixed-task product qualification, not an independent scientific replicate,
generalization, matched computation, a CPC advantage or release readiness.
