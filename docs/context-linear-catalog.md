# LS source and replay binding for the existing context catalog

The Python binding supports the complete current contextual LS source with an
explicit family choice. Existing Perceptron callers retain their original
version,16mistake requirement and native mistake diagnostic.

```python
owner = ContextCatalogControl(
    trial=request, base_snapshot=current_source_snapshot, linear_fit=True,
)
owner.require_source(
    current_source_snapshot, original_full_base,
    digest=linear_snapshot_digest, same_state=states_equal,
)
```

The request must name context-ls-12 and the exact complete source digest. Source
history must be12updates72rows, with heads8/48 and4/24, fixed D9/K6 public context
columns4/5 and complete native LS models. LS has no Perceptron mistake counter;
no placeholder16 is supplied. The option is an exact Boolean and remains pinned.
Changed source/base/digest/family/history is refused before native bank work.
This metadata binding alone does not independently prove that training happened;
the caller retains the original source receipts, budgets and ownership guard.

At bind, the actual source is checked again against the complete family history
and native digest. Candidate state/base actor version must match the same
request before bank construction. Equal aggregate counters cannot substitute
different parameters or residual/rank history. A caller cannot turn a mutable
verified report flag into admission without those checks.

The existing compose_context_replay also accepts linear_fit=True for a compatible
ordinary TRAIN runtime and ContextLinearFitLearner. It reuses the original
six-row authentic old-v1 invoice/password bank, codec,2episode4096byte retention,
native fork/success guard and independent exposure authority. Replay receipts
use CONTEXT_LINEAR_RESIDUAL_ID (squared one-hot LS residual, not CE/mistakes).
The factory does not by itself qualify a source for catalog admission.

No optimizer, controller law, replay executor or training loop is added.
Source/actor/probe/final isolation and original clocks/budgets remain mandatory.
The later [owned live catalog integration](context-linear-live-catalog.md)
provides an explicit fixed private trial through the normal CLI and records its
negative old-task retention result. The source/replay binding alone is not a
learned chooser, task-utility result or circadian/generalization claim.

The [executed integration report](reports/context-linear-catalog-20261029.md)
records one fresh ordinary source followed by private replay→wake, all receipts,
costs, failures, commands and limits. Use that evidence for binding compatibility;
use the earlier native task reports for their original useful-learning claims.
