# ADR-0561 — Reuse complete qualified BP state for actual context learning

## Context

#43 establishes known-task native BP ability, with96paid updates and full scalar
checkpoint evidence. Repeating warmup to obtain a live owner wastes training;
the old frozen reader is parameter-only2→3→2and cannot preserve SGD history.
Next uncertainty is untrained-context learning alongside old retention/return.

## Decision

Add a small BP-only record reader through existing TorchFeatureSnapshot/restore,
including exact parameters/momentum/gradients/policy/native clocks. Bind the
accepted source bytes. Restore no old application authority or budget. A fresh
isolated stream applies16prospectively budgeted updates with exact96+new offsets;
old96charges remain separately recorded. Fix both legacy/password contexts and
all readout slots before observation. No new algorithm or orchestration framework.

Why this: complete payload reuse is the minimum dependency for a substantive
learning outcome without another warmup or a general persistence/audit increment.

## Alternatives

- Reset gradients/momentum or counters: changes the qualified learner/provenance.
- Repeat96warmup: unnecessary and adds duplicate baseline training.
- Generalize codecs across all families: not required for the current BP outcome.
- Choose a failing new context after baseline: introduces favorable selection.

## Consequences

The sole case acquires legacy, transfers password initially, retains both old
tasks and keeps all four after return. Stale cases recover and revocations are
refused. No forgetting occurred, so return success is not forgetting recovery.
One known-class synthetic case does not show broad generalization or CPC benefit.
Next matched peer-family controls should reuse BP evidence and keep new peer
warmup/adaptation live, rather than adding more record/persistence infrastructure.
