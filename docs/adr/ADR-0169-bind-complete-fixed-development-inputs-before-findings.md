# ADR-0169: Bind complete fixed development inputs before findings

## Context

P6.12a preserves every independent confirmation statement. P6.12b also needs
the six original fixed development pilots. Their metric named
`final_mean_task_accuracy` uses outer-selection data. Four scored families
embed train-only preflight facts. A selected score table would lose settings,
role identities, rejected work and the distinction between the two data roles.

## Decision

First bind both original scope records, all 129 accepted source pins, both
complete scored bundles for each family, and both complete prerequisite
preflight bundles for sleep/schedule/combined/parent. Preserve all 60 raw
request/result/audit files. Compose unchanged original validators through
ports supplied only by the CLI; app logic projects every original cell and
prospective pair without selecting candidates or adding intervals.

The 120-second metadata envelope is declared before fixture execution.
It covers saved-input validation, complete projection and serialization.
Original scientific and reader budgets remain intact. Freeze source/input
identities before fixtures, retain failed checks, and require two actual
complete derivations with exact output repetition before accepting b1.

## Alternatives

- Attach only selected development summaries: loses complete settings and
  makes the interpretation vulnerable to favorable selection.
- Re-run or tune the pilots: unnecessary new scientific access and changes
  the fixed development/confirmation comparison.
- Integrate all reporting IO at once: combines heterogeneous input validation,
  hypothesis interpretation and publication before their boundaries are tested.

## Consequences

The resulting ledger is larger because it retains every raw part. Fifteen
distinct development seeds remain eighteen family/seed instances; gating
and replay share three sources. Repeated bundles add no replications. Twelve
gating/replay pairs are explicitly projected from already scored cells and
the original prospective pair list; 162 stored pairs remain unchanged.
No new metric, model, data generation, scoring, interval or winner is created.

b1 establishes current development inputs only. b2 must still join complete
confirmation/activity/cost/failure evidence and b3 must establish current
publication/readbacks before the unchanged original b/P6.12 audit.
