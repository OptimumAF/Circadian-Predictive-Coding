# ADR-0543: Explicit catalog-objective disposable probe roles

## Context

Catalog CLM training is implemented and its fixed native case is accepted, with
mixed outcomes and persistent invoice failure. Existing disposable CLM probes
support exact paired owners only. The catalog learner therefore cannot yet
participate in isolated fresh-task learnability diagnosis through that port.

## Decision

Add explicit probe_train catalog records and a catalog-specific disposable owner.
Keep exact family admission at public boundaries. Share catalog tensor/index
validation through an explicit record-kind parameter and share the existing owned
probe initialization/policy checks through protected helpers. Reuse the unchanged
directional objective, atomic update engine and permanent exposure counters.

## Alternatives

Relabeling probe data as TRAIN would blur isolation. Broadly admitting subclasses
or multiple record types into the default paired/catalog ports would weaken
their contracts. Duplicating the ownership/update engines would risk divergent
failure and accounting behavior. A new runner or checkpoint framework is not
needed for this role boundary.

## Consequences

The source remains independent, even if its training allowance is spent. Probe
work has fresh bounded optimizer state and no install/export/restore authority.
Focused behavior and affected paired/catalog integration regressions qualify
the protected extraction. This is software correctness, not native task success.
Existing temporal catalog/probe CLI cross-products stay refused until explicit
runner integration and a separate frozen protocol. Prior failures and negative
scientific results are preserved; no additional native allowance follows.
