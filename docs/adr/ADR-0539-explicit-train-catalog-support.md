# ADR-0539: Add explicit TRAIN catalog support through the native paired objective

## Context

The accepted CLM temporal diagnosis shows that invoice selects obsolete route
on its exact bare TRAIN query under v2, despite declining paired TRAIN loss.
The full active catalog contains route, but v2 paired action rows contain only
inspect and defer. Missing coverage is a hypothesis; the diagnosis does not prove
causation. Reliable conventional learning is still a prerequisite for consolidation.

## Decision

Keep the original corpus and three-row default unchanged. Add an opt-in recipe
in core.temporal_catalog_support: a new auxiliary `original workflow` TRAIN query
has the explicit current-policy target route. A remains three rows; B and return
append this support row. Native paired group-masked loss, heads, optimizer and
schedule remain unchanged. A separate repeat recipe appends the original invoice
row with its correct v2 inspect target, yielding equal44-row/twelve-update doses.

The existing app/inbox/clock/budget compose the packets and exact costs. The
outer driver shares one frozen13-template encoder/readout bank between two
independent head owners; both trajectories finish before cached scoring. All
original development records remain unchanged; support is TRAIN-only. Between-
arm baseline and first A4 prefix must agree. No new runner or checkpoint system.

## Alternatives considered

- Preserve only the original recipe: retains a useful negative control, but does
  not test a concrete response to its demonstrated full-catalog fit failure.
- Change to an unpaired full-catalog objective: requires a separately specified
  mathematical variant; this increment retains the released paired objective.
- Increase the existing dose: a distinct intervention that does not itself expose
  the missing route class within v2 packets.

## Consequences

The auxiliary rule is new supervision. Existing v2 examples must never be
relabeled to create it. Equal row counts still differ in class/group mix and
information; a recipe effect cannot establish a pure negative-only cause. Keep
all metrics, phase outcomes, original failures and costs, including extra TRAIN,
diagnostic readouts and shared encoding. No final/probe/promotion/tuning uses
these observations. Native R2.1, full R5.1/R5.3/G5/science/release remain open.

## Observed outcome

Scoped94checks/platform and statics passed; sole native comparison completed.
The new recipe fixes development invoice afterB but fails it again onreturn,
while its new auxiliary TRAIN rule itself is wrongB/return. Proper scores improve;
reliabletransfer/retention/recovery is not established. Keep both recipes optional
and preserve the original default. The original independent-review readcap failed;
producer caps pass and a separately bounded narrative finish is recorded in the
review. Next isolated nativeR2.1 probe boundary, no automatic data/dose tuning or
consolidation. [All endpoints/costs](../../artifacts/runs/clm-catalog-support-20261022/RESULTS.md).
