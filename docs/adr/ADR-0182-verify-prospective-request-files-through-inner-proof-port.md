# ADR-0182: Verify prospective request files through an inner proof port

## Context

The full role/stream metadata inspector cannot prove actual whole code/request/map
file integrity. The saved-evidence reader binds historical bodies, not these new
files. UTC/owner names and resource declarations cannot prove before-source
chronology, exclusive ownership, actual fit or independent repeat.

## Decision

Add immutable core descriptors/snapshots/results and read/recheck protocol, pure
app preflight and a strict outer file reader. Bind every caller-closed expected
code member and all canonical whole metadata files before/after app inspection.
Preserve all100 sources/480 roles/400 streams/60 views and unchanged full study.
Validate UTC/owner/resource/repeat declarations; retain all12 actual proof
obligations, unknown independence and false actual/fresh/execution/precision flags.
Why this: physically coherent full metadata is necessary before actual admission;
its declarations cannot prove the execution facts that still remain required.

## Alternatives

Trust caller hashes or decoded dictionaries: omits physical bytes and late drift.
Let app read files directly: violates dependency direction. Treat an owner ID or
UTC as admission: invents an exclusive lease/chronology proof. Adapt one-view toy
fixtures as full scientific acceptance: silently narrows the study/proof scope.

## Consequences

55 guarded cases plus249 related behavior cases pass,0skips; full mypy568/Ruff/
format/diff pass. Failed fixtures/module mapping/adversarial typing versions are
retained; final local annotation repair has identical runtime AST. No old source,
test, dependency or science changed. Caller-closed membership remains separate
from runtime closure. All25 helper cases, actual lease/source/prior/resource/
repeat/b3 proofs and parent acceptance remain required. Original failed cap and
negative precision remain unchanged; no positive actual admission is exposed.
