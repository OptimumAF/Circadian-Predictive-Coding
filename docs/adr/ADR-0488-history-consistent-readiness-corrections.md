# ADR-0488: history-consistent readiness corrections

## Context

The history47 learner completed a bounded native qualification with zero success.
It could not consume existing on-policy readiness supervision because its frozen
collector refused corrective queries/roll-in. That is a demonstrated composition
gap; another feature or algorithm is not yet justified.

## Decision

Derive an owned47D readiness view from original raw42 executed transitions, then
pair original provisional targets/stages/arrivals with those causal observations.
Use the existing eight-update private runtime and frozen return. Preserve actual
mixed commands and paid student predictions during bounded teacher roll-in. Own
and pin the original recipe/reset/source before callbacks; finish query capture
while SDK is live and verify sealed raw evidence through final release. Share
existing stronger native owner/clock/budget/receipt checks for either historymode.

## Alternatives

Using teacher targets as history would leak unsent actions. Broadly ignoring
counter changes or renewing budgets would weaken existing authority. A separate
training/orchestration framework adds duplication. A taskspace representation is
deferred until this available supervision can be tested on the current learner.

## Consequences

All four neural families can use existing correction flow without refit or source
mutation. Extra projections, copies, native prefix folds and serialization cost
computation/memory; they are not free because SGD counts match. Query/prefix
success is not pure-student success.62tests/platform and independent review accept
this scoped software; no native benefit, final-data access or CPC advantage follows.
