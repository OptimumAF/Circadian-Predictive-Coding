# ADR-0625: First-party affine training and native games

## Context

The conventional affine learner fits known TRAIN contexts and has executed
complete known games. Its scientific commands require historical local reports
and exact accepted-source hashes. This prevents a normal installed user from
running the learning path without the research archive. Isolated fresh-task
diagnostics also show interference; they do not establish a circadian benefit.

## Decision

Package only the six original project-generated TRAIN episodes. Add one explicit
mode to the existing linear CLI and a narrow composition module. Extend the
existing delayed stream with opt-in ABC/capacity2 scheduling and a successful
native endpoint callback after receipt capture. Pass that actual endpoint to
the unchanged known B/C game evaluator. Preserve old stream defaults and all
historical scientific source qualification.

Why this: useful first-party execution needs normal data ownership and complete
runtime receipts, not restoration of historical experiment authority. Reusing
the stream and evaluator avoids a second orchestration framework. The existing
paid-report guard refuses edits and container replacements during later work.

## Alternatives

Shipping fitted checkpoints would skip learning. Requiring the artifact archive
would preserve the usability gap. A new runner or generalized source loader
would add infrastructure without improving the learned behavior.

## Consequences

The package gains about 95 KB of public synthetic TRAIN data and a console
entry point; no new dependency. Fits and joint replay exposures are explicit.
Native MiniGrid remains optional and known-task success supports only that
scope. Clean dependency installation, release readiness, unseen layouts,
recurrent RL and scientific comparative benefit remain separate requirements.
