# ADR-0505: retain all released rows in the corrective fit

## Context

The accepted112 student fails Push and loses old Pick success. Fifty labels now
describe its actual visited states, but all are align-stage labels. The original
18 expert rows retain later-phase supervision. Keeping both plus80 old TRAIN
references requires148 rows; the existing mixed adapter admits at most130.

## Decision

Raise only explicit mixed continuation admission and native recording limits to
148 rows. Keep head-GN130, default8, mixed maximum64, native optimizer, objective,
normalization, inherited momentum, receipts, clocks and bounded storage unchanged.

Reuse the existing study and frozen runners. Qualify the complete original hashed
correction release with core history/arrival checks and exact packet/receipt/work
binding. Reconstruct accepted112 and its readout before one separate eight-update
scope on all148 rows, then one fixed Push17/Pick17/19/20 physical endpoint. Keep
source40/48/112 frozen and preserve failed evidence before admitting further work.
No post120 TRAIN readout or dose chosen from physical outcomes.

## Alternatives

- Drop original18 to retain130 rows: loses observed later-phase supervision to
  satisfy an engineering limit; no scientific reason supports that omission.
- More updates on only expert data: the accepted64-update result already improves
  TRAIN fit without physical acquisition and worsens retention.
- New optimizer or orchestration framework: the existing API can fit these labels.

## Consequences

New outer intake and focused tests, no dependency or numerical-kernel change.
The fixed fit charges1184 new row exposures and the reconstruction again. Native
success, retention and computation must be recorded even if the outcome is negative.
Scope completion does not establish reliable adaptation, recovery or CPC benefit.
