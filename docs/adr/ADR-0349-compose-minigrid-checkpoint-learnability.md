# ADR-0349: Compose MiniGrid checkpoint learnability through the existing stream

## Context

R2.1 already has feature diagnostics and disposable probes. Native MiniGrid
148-feature/K7 packets and reserved E roles now pass component checks, while
two full live-readout cases exhausted their wall budgets. The learner question
still needs measured new-task fit, old-task retention/return and cost.

## Decision

Add one opt-in scenario to the existing attribution CLI. Reuse guarded `_train_arm`
and its owned five checkpoints with the same128update benchmark. After every
method finishes training, measure known-TRAIN raw sequence fit and fixed16update
disposable probes from checkpoints0/128, using the existing probe API and
original-deadline-limited independent charges. Preserve all curves and failures.
No final D is constructed or used for decisions in this diagnostic recipe.

Why this: the accepted stream, episode, native state and probe contracts already
provide the required boundaries. A focused adapter composes those ports, retains
their receipts/guards and exposes measurable work without another runner.

## Alternatives

A separate trainer would duplicate native objective, delayed-label and ownership
behavior. Treating the failed full-readout gate as passed would change its
scientific criterion. Unplanned repeated doses/seeds would allow selection from
observed outcomes. All remain outside this increment.

## Consequences

The scenario adds diagnostic computation and reserved exposures; report them
separately from the benchmark. Fixed same-family deterministic E traces do not
establish generalization or isolated plasticity. Raw teacher-forced acquisition
is not live skill. The original full160live gate, useful adaptation, comparative
benefit and release requirements remain open unless their own evidence passes.
No dependency, environment variable, learner objective or baseline is changed.
