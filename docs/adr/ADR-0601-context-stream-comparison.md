# ADR-0601 — Shared scenario preview and finite missing-controller comparison

## Context

The24-step recurrence/noise engineering cases omitted several scenarios in their
pre-run description. Repeating periodic training would spend work without fixing
that historical qualification. Existing scalar controller fit and runner are
already available; missing applications can test behavior on the new recipes.

## Decision

Extract pure serving_opportunity/serving_preview and use the same mapping in the
worker. Freeze an independent literal24 table before new applications. Compose
the existing live runner/objective for exactly ten missing cases, preserving the
two prior periodics as limited retrospective engineering data and the frozen fit
as scalar data. Validate all twelve before scoring; stop on uncertain paid work.

Why this: the concrete dependency was an explicit scenario contract and missing
controller applications, not another runner or baseline retraining framework.

## Alternatives

Backdating a complete periodic protocol would misrepresent evidence. Silently
omitting denial22 would change the metric. Refitting from these outcomes, forcing
pending work to drain or renewing budgets would alter the frozen comparison.

## Consequences

Defaults and historical negatives remain. Pending updates, learned shadow state,
guard acceptance and served task outcomes must be reported separately. Fixed
serial order/asymmetric diagnostic and publication costs prevent efficiency
claims; the fit's proxy mismatch and periodic protocol omission remain. New
comparisons require their own prospective protocol, not automatic dose/seed tuning.
