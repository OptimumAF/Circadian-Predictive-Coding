# ADR-0438 — Explicit H32 admission for the existing isolated probe

## Context

The original R2.1 MiniGrid joint-catalogue diagnostic already owns source/actor
isolation, frozen readers, two F16 cohorts and their same-optimizer A16 returns.
Its factory and native checkpoint admission explicitly require H8. The accepted
fixed H32 quartet fits the same TRAIN catalogue; BP completes one known A cue,
fails the other, and all PC-family games fail. Learning a fresh task and reading
both old-A cues now requires admitting that genuine H32 checkpoint recipe.

## Decision

Add exact-bool `wide_neural=False` to the existing learnability API and an explicit
CLI flag. True admits only the original four methods on the fixed H32 joint54-row
128-update F16/old-A/A16 route. Bind full native policies and both clocks at every
existing checkpoint boundary; do not infer authority from supplied weights.
Direct private wide probe admission also requires the original F pair.

Reuse the original stream, disposable probe, return phase, guards and permanent
budgets. H8/default callbacks and descriptors remain unchanged. Keep benchmark,
F, A-return, monitors and derived native work separate; unobserved failure does
not certify optimizer work. No native objective or update rule changes.

## Alternatives

- Build another H32 runner: duplicates isolation and budgeting behavior.
- Accept arbitrary snapshot widths: silently broadens a frozen recipe.
- Select only the successful red cue: discards the failed blue control.

## Consequences

The public path can execute the existing isolated diagnostic from H32 checkpoints
while preserving old behavior. More capacity and equal row exposure do not imply
matched computation, useful adaptation, retention/recovery or CPC advantage.
Synthetic engineering qualification precedes a separately frozen and reviewed
original-source comparative experiment; its result may be negative.
