# ADR-0181: Validate the complete prospective role/source/request metadata

## Context

The public stream gate binds60 views/50 planned groups/all400 streams but lacks
the complete source/role/request envelope. Actual B exposure retains original
row positions when reducing120 development rows to60. A dense0..59 metadata
validator would reject existing behavior. Physical provenance and historical
release/resource acceptance remain unresolved.

## Decision

Add frozen core records and pure app inspection for100 phase-source declarations
and480 ordered roles, composed with unchanged full-design/stream validators.
Bind canonical whole design/source-map/request metadata identities, exact
expected code declarations, all data-generator arguments, policies/counts/IDs and
all12 actual-proof obligations. Keep B positions in the original0..119 universe,
all role partitions disjoint and planned shared views equal. Reject unknown
schemas/types, detached/resealed scope drift, premature release and execution.
All actual proof flags stay false and independence unknown. IO/provenance is
reserved for outer adapters through inner ports; no arrays/RNG/model work here.

Why this: complete metadata integrity is a necessary inspectable boundary before
source construction, while actual producer/UTC/history/resource proof requires
different evidence. Source configuration hashes exclude model/sleep parameters;
the full design continues binding those settings and shared data views agree.

## Alternatives

Use released-array role validators: requires actual source/arrays and crosses
the pre-source boundary. Accept equal dataclasses/checksums alone: accepts
value-equal bool/float coercions, wrong partitions and resealed scope changes.
Renumber B densely: changes existing original source identity semantics.

## Consequences

54 new guarded cases plus120 related cases pass; full mypy563/Ruff/format/diff
pass. Initial missing API/fixture/local typing failures and exact versions are
retained. No old source/test/dependency or scientific settings change. Actual
source/role/code/chronology/independence, original25 helper cases, failed resource,
negative precision and all full b2/b3/d2b/d2/P6.7/d3 acceptance remain required.
