# ADR-0167: Present all original outcomes against scoped costs

Status: accepted and implemented. P6.10b2/b3/b and the original P6.10 parent
pass their complete separate acceptance; P6.12 and broader work remain pending.

## Context

The accepted complete report stores all 560 outcomes, six metrics per cell,
all 626 arm/contrast vectors and 116 original primary interval statements.
Its compact cost references bind raw context files but do not contain their
whole histories/retention proofs. P6.10a and b1 separately validated and
published those complete facts. Input schema inspection 2910d2fe...e3da,
5,297 bytes, binds all three whole original bodies and prior handoff with
24 zero scientific boundary calls; it is not a new official reader run.

## Decision

Implement a pure three-body join/presenter first (P6.10b2), then the complete
official-report-reader port, exclusive publisher, fixed CLI and actual
publication/repetition/readbacks (b3). Preserve the original b and parent
acceptance unchanged. Whole canonical input byte identities gate the public
pure consumer; a private development seam grants no artifact/source authority.
Pure validation checks all scope/counter/capacity/state/parameter/owned/shared
links and preserves complete outcome, cost, history, retention, analysis and
interval records. JSON contains every proof and pointer; Markdown includes
complete per-cell compute and memory tables plus all shared and historical
resource scopes. Repeats add neither work nor seed replications. No new metric,
pooling, subset, model winner, profiling, source or scientific settings.

Why this: independently testable pure joins keep scientific/IO responsibilities
clear and make a wrong resource attribution detectable before publication.
Retain null views and unmeasured per-arm wall/RSS/guard duration. Derived owner
array bytes and shared FIFO are different scopes from Python overhead,
checkpoint copies, process RSS and different stage snapshots.

Prospective budgets, before new development fixtures: **120 seconds per local
pure saved-input validation**, and **240 seconds per future full consumer
operation**. Prior unchanged full report/matrix reader processes took 176–178
seconds; source/input/retention preservation took 31 seconds. The new full
consumer adds two complete retained-metadata ledgers and joint rendering;
240 seconds is its separate derivative envelope. Existing original report
reader's own 180-second gate and scientific 16,000-update/600-second/512-MiB
caps stay unchanged. Declare and freeze each complete new source/request
contract before its corresponding fixtures and actual operations. No sweep.

The first full publication revision passed its IO gates but hit the hard
240-second derivative timeout during final bindings after a 232.5041207-second
audit. A remaining claim makes that five-part saved bundle incomplete. Preserve
the timeout, all partial parts and exact source/test/producer snapshots; grant
no actual success from a nonterminal completed audit. Snapshot preservation is
ec19ef52...4257/6,395 bytes. Code inspection found immediately duplicated whole
binding traversals. Pass the just-validated request within one operation, check
its whole saved bytes before the unchanged official reader, reconstruct every
binding after the whole derivation and again at final publication/readback.
No cross-operation cache, narrower reader, skipped field, cap increase or
scientific change. Freeze this small repair before fresh IO fixtures and use
distinct unoccupied v2 directories. Original acceptance remains unchanged.

## Alternatives

- Reconstruct all histories from compact report rows: insufficient because
  their complete shared contexts are only referenced.
- Divide historical process costs or group memory across arms: unsupported
  attribution; retain their actual scopes.
- Add isolated per-arm timing now: a separate measurement would require a
  prospective protocol and an original-parent audit establishing its need.

## Consequences

Three small app modules own pure validation/composition/rendering. Later infra
receives the unchanged full official reader; only the CLI composes adapters.
Existing modules, scientific sources, report/retention/inventory bytes and
protocols remain unchanged. Missing/failed/null/negative/above-one/rejected/
inactive observations survive. Check b only after every original criterion,
including all four actual full-reader operations, then audit original P6.10
and produce the explicit P6.12 hypothesis conclusions. Pure tests and stored
metadata reconstruction alone cannot close those requirements.
