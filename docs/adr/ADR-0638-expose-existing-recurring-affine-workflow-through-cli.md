# ADR-0638: expose the existing recurring affine workflow through the CLI

Status: accepted for CLI composition and scoped installed Windows delivery.

## Context

The existing recurring_training=True API learns original G while retaining ABC,
returns to A and plays known G/A games. The existing command exposes normal and
private modes, but not this ordinary recurring recipe. Prior installed-package
evidence predates G support. Source-only success does not prove installed delivery.

## Decision

Add --example-affine-recurring to the existing mutually exclusive command modes.
Describe delegates to existing metadata before any IO/native work. Execution
delegates to run_workflow(recurring_training=True), with the same bundled source,
original teacher, stream, fits, replay exposure, games and budgets. A local
first_party flag keeps shared source/output admission consistent across three
example modes. Old defaults and their exact call signatures remain.

## Alternatives

A separate command or runner would duplicate established behavior. Exposing fit,
seed, private/final or checkpoint knobs would change the fixed recipe. Reusing an
old installed wheel would not test current CLI/code/resource delivery.

## Consequences

The first-party recipe is runnable without a research archive or saved model.
JSON output remains exclusive, capped at4MiB, with failed prefixes and exit2.
No new dependency, learner, role permission or scientific claim is introduced.
Installed delivery needs its own bounded wheel/isolated-target/native validation;
repeated fixed tasks are engineering qualification, not independent science.
Final D outcomes never tune or enter this TRAIN workflow, and failed neural or
private studies are not retried. Broad clean-clone/dependency/platform/release
requirements and circadian benefit remain separate open criteria.
