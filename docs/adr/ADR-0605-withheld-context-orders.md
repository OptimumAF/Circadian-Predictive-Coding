# ADR-0605: Validate frozen classifier choices on complementary packet orders

## Context

The original recurring clean/noisy comparison used one packet order/delay.
Correct-TRAIN acknowledgements now have a separate verified runtime path.
Neither prior application can serve as a matched control after changing its
packet schedule. Failed task-fit87 is not a qualified trained policy.

## Decision

Add two immutable balanced complementary recipes and an explicit API/CLI option
to the existing comparison. Execute seven frozen modes afresh for each recipe,
reusing only qualified source77 and classifier fit82. Validate dynamic receipt
clocks/indices, cumulative native work and separate acknowledgement progress.
Keep the original default protocol and saved-evidence admission unchanged.

Why this: a small prospective validation answers whether frozen choices travel
to new packet schedules without adding another runtime or retraining controls.

## Alternatives

Reusing old periodic applications would mismatch data order/delay. Refitting or
retrying87 would spend an unavailable scientific allowance. Extending this study
to88 task units would change the scoped classifier question without a qualified
trained task policy. The scope explicitly excludes that all-heuristic claim.

## Consequences

Fourteen fresh cases incur native, diagnostic and retained-report costs. Joint
order/delay changes and known task templates limit interpretation; serial cost
proxies cannot establish efficiency, broad generalization or CPC advantage.
All failures/negative results remain, and broad R7.5/release requirements stay
open regardless of this scoped outcome.

The sole invocation exposed a retired-policy selection after verified drain
publication. Preserve direct stale-policy refusal; the owner now explicitly
waits for the service-only tail after checking the original captured publication
and complete drained state. This is software retirement, not a new fitted policy
or permission to rebind it. The failed cohort remains unchanged/no retry;
scalar checks do not qualify a repaired native continuation.
