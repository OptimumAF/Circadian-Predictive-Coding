# ADR-0597 — Reuse periodic evidence in contextual reference comparison

## Context

The conventional contextual learner now demonstrates guarded acquisition and
retention. Existing fixed references and objective should be tested on that
learner before adding a new adaptation mechanism. Periodic already has accepted
evidence; the native BP fitted controller belongs to another source/version.

## Decision

Expose exact existing reference modes in the contextual live API/CLI, preserving
periodic defaults. Distinguish a completed finite serving horizon from completion
of planned TRAIN. Run only the three missing controls in a frozen order, validating
prior paid records through the existing guard before another admission. Reuse
the byte-pinned periodic report as data. Score the same task/scenario window
against no-learning with the unchanged objective, after all cases complete.

Why this: one finite composition answers the fixed-control question without
another runtime, repeated baseline training or policy fitting from evaluation.

## Alternatives

Rerunning periodic would spend already-paid work without resolving a source
change. Forcing drain or changing reserve/threshold values would change the
declared controls. Applying the old fitted chooser would violate its learner
version binding. None is part of this comparison.

## Consequences

Only periodic publishes and serves6/6 common tasks; others serve5/6. Drift's
unapplied repair blocks drained publication, not necessarily learning. Reserve4
against2credits makes budget-aware wait. Full case cost asymmetry and retained
heap prevent efficiency claims. The failed initial test selection lost profiler
accounting; unknown native costs remain unknown. A minimal fatal guard repair and
narrowed final88 checks/platform passed before the sole new comparison. Broad
scientific and release criteria stay open; source/procedure/result review is
scoped and independent readback is not independent numerical replication.
