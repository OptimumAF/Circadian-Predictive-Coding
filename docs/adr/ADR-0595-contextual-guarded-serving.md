# ADR-0595: bind conventional contextual learning to existing guarded serving

## Context

77qualifies four known contextual workflows;78privately acquires legacy tasks
but also exposes within-head regression. Native serving bindings require Torch
snapshots and tensor-only byte accounting. Context readonly prediction rejected
mixed guard batches despite generic promotion ports accepting them.

## Decision

Allow mixed readonly context batches, keep homogeneous TRAIN. Add a small NumPy
serving adapter with complete validated canonical JSON state bytes and the
existing required digest callback. Use the existing stream/actor/guard/controller
through an explicit existing serving CLI mode. Keep numeric guard thresholds;
name the resource metric accurately. No source78probe weights enter deployment.
Measure point1 but publish only point2, after all planned training. Preserve
partial episode/read prefixes before later work; original receipts own rollback.

## Alternatives and consequences

Reusing Torch tensor bytes would incorrectly report tuple coefficients as0B.
A new serving runtime duplicates existing authority and publication mechanisms.
Worker concurrency is a separate useful next boundary; it is unnecessary to
first establish a useful guarded publication and would enlarge this slice.
Known TRAIN guards are not heldout evaluation. Original native defaults stay.

One source77-based case rejects old row regression, repairs through fixed TRAIN,
publishes6/6known tasks and rolls back exactly. The frozen control remains5/6.
Extra9rows/guard/build/typed work is charged; no efficiency or CPC claim follows.
Independent finite read-only review found/fixed partial-evidence loss and meter
limit discrepancies; it does not establish broad scientific/release acceptance.
