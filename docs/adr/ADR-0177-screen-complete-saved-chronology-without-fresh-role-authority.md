# ADR-0177: screen complete saved chronology without fresh-role authority

## Context

The original complete prior-evidence repeat timed out. Its shared360-second
budget has350.7925872spent and9.2074128remaining. A complete fixed lexical
comparison preserves behavior but finds the candidate5.69%slower; the production
reader remains unchanged. Neither saved-byte equality nor that metadata result
repairs resource acceptance or proves untouched roles.

The entire saved evidence retains numeric declarations, quantities, policy nulls,
inventory lineage, defaults, dynamic expressions, opaque/unparsed/unreachable
contents and physical/Git aliases. These are different from verified construction,
execution or actual label release. Commit/path and copy order establish documentary
availability, not the time labels were opened. Current confirmation code also binds
an eighth stream, circadian local RNG at base+11002, beyond the earlier short list.

## Decision

Add a separate complete saved-corpus validator and conservative chronology
projection. Validate exact whole physical/Git membership and every ordered alias,
content section and witness. Bind the entire original saved record for each content
by whole canonical digest and original input pointer; retain every witness in the
immutable full input instead of duplicating millions of text/expression records.
Count numeric declaration occurrences conservatively, excluding known quantities
and nonrandom null policies. Copies and inventory lineage are not independent trials.

Screen caller-declared ordered bases against all current source/split/exposure/model/
selector/local-noise numeric streams and against other proposed streams. These are
possible numeric collisions, not evidence of executed sources. Never choose actual
candidate seeds or grant admission. Unknown execution and release remain explicit,
including symbolic, opaque, unparsed, unrecorded and unreachable provenance. This
consumer newly verifies zero execution/release events; it does not assert that
historical execution or release never happened.

Why this: a stable conservative interface lets the remaining original b2 bind
verified chronology and the complete future contract without turning missing
evidence into freshness. Keep this component separate from the unchanged semantic
reader and scientific/model/source layers. No new dependency or configuration.

## Alternatives

- Treat all declared numbers as executed seeds: confuses quantities, inventory
  lineage, unexecuted defaults and documentary copies with actual trials.
- Admit a base absent from JSON fields: misses derived-stream reuse and unknown
  historical releases, including local circadian RNG state.
- Infer release order from Git or copied filenames: unsupported event chronology.
- Rerun the failed full semantic reader under a new envelope: resets exhausted
  original budget; this projection retains that negative resource result.

effects conservatively bounded, the original resource acceptance, fixed independent
ordered roles/config/count/analysis/stopping/source/request and full b3 fixtures.
