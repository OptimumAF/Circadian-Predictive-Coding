# ADR-0368: Reuse isolated probes after incident replay

Date:2026-10-17. Status: corrected source and offline saved behavior accepted;
original native qualification remains incomplete.

## Context

The existing shift pilot rehearses after incidents and measures A/B retention/
return, but does not measure whether those checkpoints can learn C. The matching
reserved C task,16-update facade and diagnostics already exist. Snapshot array
costs differ between PC and neutral CPC by native auxiliary state.

## Decision

Compose that facade only at recurring0/6/12/18 behind explicit --learnability.
Supply four original setup sessions via an optional prepared-budget argument;
legacy callers keep prior behavior. Use an independent template/disposable forks,
retain full curves/health and partial paid work, and defer benchmark finals until
every required observer/probe completes. No final-data selection or feedback.

Validate PC snapshot arrays840B and neutral968B at each probe checkpoint, retaining
the128B cost gap, before comparing every other semantic/work field. Preserve the
original failed equal-storage gate/raw data; verify corrected source against
saved data without retraining.

## Alternatives

A new probe/runner would duplicate accepted code. New budgets at checkpoints
would obscure original allowances. Ignoring all memory counters would hide real
costs. Rerunning the same paid study adds no information needed for this repair.

## Consequences

The new run spent432updates/3232rows and saved full new tensors. Offline review
confirms benchmark isolation and PC-neutral parameter/diagnostic/learning parity.
Warm PC/CPC C endpoints remain negative; BP gains remain positive. This is not
causal plasticity loss, equal-compute improvement or a CPC advantage. The separate
unplanned8update legacy test is a preserved budget violation, never a retrospective
budget pass. [Evidence](../../artifacts/runs/r21-incident-learnability-20261017/RESULTS.md).
