# ADR-0587: Use the owned probe to separate fit and task learning

## Context

Saved-state diagnosis shows v1invoice still chooses inspect after four updates.
Original R2.1 already provides isolated probes, old-TRAIN monitors, fixed return
and protected endpoint callbacks. Native BP qualified96 and original0 states are
available under the same recipe; no new baseline fit or probe framework is needed.

## Decision

Compose these interfaces in a small fixed recipe. Probe v1invoice/password for16
alternating three-row updates; retain all0/4/8/16global categorical metrics and old
TRAIN monitors. Return to original v2invoice/parcel for16updates on the same fork
and optimizer under a distinct finite session. At both endpoints run four bounded
typed sandbox episodes on protected native copies. Warm96 precedes fresh0; reject
incomplete or changed previous paid evidence before more work. Preserve source,
data, owners, clocks, budgets, RNG and all failures. No final data or promotion.

Why this: row loss and task success answer different questions, and retained
old ability must be separate from ability to learn a changed task. Existing
owner/observer interfaces already supply the necessary isolation and accounting.

## Alternatives and consequences

Extend a controller sweep: does not resolve the learner fit gap. Rebuild a probe
runner: unnecessary duplication. Tune dose or select seeds to get acquisition:
incompatible with the frozen diagnosis. Infer plasticity loss when warm fails:
unsupported without sufficient identifiable learning evidence.

Before execution, record that old-v2 and new-v1 ready-invoice have the same D7
input and incompatible labels, with both actions allowed. Do not call simultaneous
failure generic forgetting. Actual frozen case completes64updates/192rows but
warm invoice still fails and fresh solves no endpoint tasks. Warm old tasks and
password remain successful; no recovery from a lost task occurs. Preserve every
curve and all costs. Next expose observable policy context through the existing
feature path while preserving old defaults, before any new conventional fit.
