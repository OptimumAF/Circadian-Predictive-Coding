# ADR-0558 — Native families share the original chronological task recipe

## Context

#40 provides complete frozen typed native checkpoints; #39 already exercised
the original recurring stream and complete tasks. Actual BP/PC/CPC acquisition,
retention and return on those tasks remain unanswered. Existing defaults must
stay runnable, with negative results and genuine costs preserved.

## Decision

Add an explicit native method to the same recipe loop, with a small helper for
counted native forks and complete scalar checkpoint/cost records. Keep the
existing teacher/dose/delay/episode slots, native algorithms/defaults and frozen
typed callback. Native replay is excluded explicitly from this fixed observation.
Use original wake budget, complete source/seed guards and detached readouts;
record counters, full native state and initialization/copy/gradient work honestly.

Why this: using the same task loop makes actual task failures comparable at
declared endpoints without another scheduler or hiding native state differences.

## Alternatives

- A second native runner: duplicates schedule/effect/metric logic unnecessarily.
- Parameter-only records or perceptron cost labels: lose native history/costs.
- Increase fit or add circadian mechanisms before observing defaults: makes
  negative default behavior harder to interpret and invites outcome tuning.

## Consequences

Recorded same-dose native case fails every full ordinary task. BP learns two
steps atA but does not complete; PC-neutral traces match. Neither zero forgetting
nor return metric proves retention here. Conventional TRAIN fit/action-margin
diagnosis takes priority over new mechanisms. Native objectives/compute differ;
no scientific superiority, generalized learning or release readiness follows.
