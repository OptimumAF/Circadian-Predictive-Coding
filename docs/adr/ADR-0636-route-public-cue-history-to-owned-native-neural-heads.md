# ADR-0636: route public-cue history to owned native neural heads

Status: accepted for the bounded implementation; scientific outcomes are separate.

## Context

The analytic ordinary TRAIN workflow demonstrates new-task learning and known
game success. Prior MiniGrid neural and Perceptron failures remain. The original
Torch feature policy supports296 inputs; its existing representation routes pool
both cues. Public-cue head separation already exists for other learner families,
but no usable two-native-neural-head binding existed at issue125 inspection.

## Decision

Add one adapter owning two complete original native snapshots. The established
public initial cue chooses a head, and the established canonical296 projection
feeds it. All four native methods share capacity and initialization contract.
Native math, defaults, optimizer/chemistry/unit/RNG state and old wrappers remain.
Fork/restore copy complete data; actual operations stage original native ports
and pay every construction/draw. Keep one permanent failed-attempt scalar record
with the detached preceding prefix, refusing continued use or failure erasure.

Compose a single conventional BP known-A qualification in the existing control
module, AttributionStream and native evaluator. Fixed128alternating nine-row
TRAIN updates and post-fit detached monitors precede two known games. The route
checks full receipt/counter geometry and original source, actor, reports, protocol
and clocks. The optional endpoint observer returns owned data, no runtime
authority. Existing finite orchestration closures remain in the control module
to keep related admission, failure capture and accounting together; no general
scheduler, loader, checkpoint service or new configuration framework is needed.

## Alternatives

Another pooled fit would repeat an already observed learning/control limitation.
Changing objectives or adding circadian features before a useful conventional
baseline would confound the diagnosis. A wider native policy or new runner adds
unnecessary surface. Saving only weights loses momentum, gradients and owned
adaptive/RNG continuation; saving runtime authority would renew spent budgets.

## Consequences

This explicitly adds a second head, so old pooled comparisons are not matched
capacity or causal evidence. Per-head clocks advance only on routed work; global
clocks sum them. Repeated staging is expensive but measured; optimization requires
a demonstrated profile and preserved equivalence. Software parity/isolation and
literal admission tests cannot establish game success. The separately frozen
one-case result may be negative; it cannot authorize tuning/retries or a CPC win.
Full scientific, generalization, reliability and release requirements stay open.

## Paid-prefix ordering correction

Actual execution returned128updates but failed before the endpoint callback,
losing the full state. The existing data-only observer now runs at the first
validated128-receipt/native-counter prefix before fallible finalization. It
exports an unqualified prefix, with finalization tracked separately. Receipt,
full-state, original runtime and authority checks still gate finalization and
all later scoring/games. A failed observer or finish cannot confer qualification
or discard data already retained by the caller. No new persistence layer or
scientific allowance is added; historical failed states cannot be reconstructed.
