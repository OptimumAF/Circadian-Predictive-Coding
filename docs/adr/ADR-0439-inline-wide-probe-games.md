# ADR-0439: Reuse inline games on H32 disposable endpoints

## Context

The accepted original H32 F16/A16 study measured fixed-row fit, not post-update
game control. The existing inline observer admitted count states with nine rows
per update; H32 joint benchmark passes use54 rows and probe/return passes nine.

## Decision

Extend the existing observer/evaluator behind the exact explicit H32 recipe.
Bind full owned native state to the actual disposable endpoint and the mixed
exposure law. Reuse four fixed target-free A/F games, complete boundary guards,
bounded paid reports, readonly child budgets and the original parent clock.
Keep the legacy joint-training validator unchanged; exact H32 admission in its
facade owns the new optional game authority. Disabled and count routes retain
their established behavior. No learner objective, dose or comparison is changed.

## Alternatives

A new orchestration or deferred capture framework duplicates working machinery.
Accepting width/counters alone cannot establish the owned preceding endpoint.
Using the old nine-times-total law rejects valid joint-trained endpoints.

## Consequences

Actual games add prediction/physics/copy/validation costs but no training/replay.
Failures retain paid prefixes and unknown lost work. Engineering qualification
uses one synthetic actual chain and structural/fake-physics fixtures, and cannot
establish original-source adaptation or comparative benefit. Comparative games
need a separate small protocol with unchanged seeds/metrics and all failures.
See [usage and checks](../wide-neural-probe-games.md).

## Follow-up: qualified reads and prospective wall allowance

The original20s public qualification failed; grouping existing native proofs
advanced from12 to42steps before the same cutoff. The app boundary now supports
a final native proof after its original clock reads. This closes a demonstrated
late-clock mutation gap and avoids duplicate frozen feedforward session reads.
A prebound plain-scalar report comparison preserves exact owner/type/value checks
on every call; opaque/drifting/NaN reports keep the original fallback. Independent
legacy-oracle tests cover error and callback behavior, including custom metaclasses.
Neither optimization caches a validity result across external work.

Explicitly revise the inherited agent-created20s engineering setting to40s for
future fresh H32 children, equally for all four methods. Count20s and original
parent180s/RSS/clocks/zero training/replay/permanent charges remain fixed. This
prospective change is recorded before execution; all old20s attempts stay failed,
are never renewed, and do not become20s passes. Future comparative protocols must
freeze40s and disclose costs. The new public qualification remains separate from
the passing focused checks and any scientific/release claim. Why this: measured
H32 costs justify bounded wall headroom without another native inspection layer.

## Follow-up: immutable scalar identity reads

The fresh40s chain still failed in its second cohort. Most outer proof repeats
straddle external snapshot/clock ports, so retain their fences and simplify the
existing app scalar proof instead. Full exact builtin equality is established
at binding, including protection against opaque deepcopy side effects that
leave unequal pure trees. Each call then reads every actual/trusted owner, key,
shape and child/scalar identity using captured strong references. Immutable
builtin leaves cannot change behind an unchanged identity. This is a fresh
per-call proof, not cached validity. Any drift takes the original dynamic proof;
equal replacements and legacy trusted edits remain supported. Opaque/NaN/error
behavior stays unchanged. No additional runtime limit increase is permitted.

## Follow-up: reuse the owned checkpoint already validated

Source128-only cProfile confirms that the bound checkpoint path first copies and
validates native state in its counter, then immediately copies the original
input again with no external port in between. Factor this existing body into a
private returning helper; keep the existing counter's None result. The caller
returns exactly the owned state whose policy and clocks passed validation. This
also avoids rereading an original that changes after the validated copy.

Every call still makes a fresh complete owned native copy. Original point/row/
policy gates, tensor/optimizer/gradient/adaptive/RNG validation and all external
snapshot/clock/evidence fences remain. The source-only profile's ~2.180s residual
within39.315s is component evidence, not a whole-chain or learning-benefit claim.
The existing public qualification remains the acceptance test under40/180limits.

## Follow-up: explicit bounded readout envelope

Repeated measured validation repairs leave source128 F incomplete at57/64 steps
in40.045s. The remaining cost is mandatory proof around external ports. Rather
than another speculative guard/inspection framework, add an explicitly selected
fixed H32 resource option:60s endpoints/240s body/270s outer. The original40/180
acceptance remains open and every failed run remains failed. This prospectively
supersedes this ADR's earlier agent-created prohibition on future limit increases;
no user limit or scientific criterion is changed.

Each selected budget is new, born once with its fixed limits. Source/data/native
objectives/seed/dose/metrics are unchanged, all four matched methods receive the
same option, and prior evidence/clock/charge/isolation guards remain. Default and
count routes retain their old budgets and descriptors. Consequence: a completed
selected case proves runnable integration only under its declared envelope;
future comparative protocols must freeze that choice and report full compute,
probe, validation and memory costs. It cannot satisfy the old latency gate or
establish useful adaptation, circadian benefit, heldout RL or release readiness.
