# ADR-0545: Catalog learning with explicit TRAIN support recipes

## Context

The accepted catalog learner and isolated probes show partial learning and
severe disposable-probe old-task damage. Existing paired repeat/route recipes
supply an explicit equal-row conventional control, but catalog mode rejects them.
No additional ownership or checkpoint mechanism is required for this missing path.

## Decision

Compose the existing catalog learner with the existing recipe declarations,
feature builder, causal app and two-owner comparison. Bind phase-specific3/4/4
query packets to full3candidate banks and indexed TRAIN labels. Charge candidate
and logit exposures separately from query-target pairs. Admit both objective-
specific complete prefixes/caches and shared A parity before cached scoring.
Reuse existing main TRAIN/development diagnostics in the same fixed comparison.

## Alternatives

A new runner duplicates existing orchestration. Additional isolated diagnostic
runs spend encoder work without delivering the missing recipe baseline. Selecting
new markers, doses or metrics from probe outcomes would change the question.
The new path therefore preserves existing corpus, math and frozen directions.

## Consequences

Paired and none defaults remain; catalog support plus reserved callbacks is
refused, and the older paired generic-callback API is preserved. CLI support/
reserved refusal remains. Equal native work differs in class/group/unique data.
No retention remedy or circadian advantage is assumed; all old/new task negatives
and failed allowances remain. Historical paired13 use needs explicit source/
environment/text/token/control/baseline binding; no12/13/16 parity assumption.
Software, executed task usefulness, scientific claims and release are separate.
