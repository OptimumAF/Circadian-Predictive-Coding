# ADR-0130: Preflight the legacy policy sweep's training work

## Context

P5.5 requires bounded experiment execution. The fixed v14 study already
binds replay retention and structural capacity, while the legacy
`run_circadian_policy_sweep.py` builds 18 candidates and initializes Torch
and synthetic data before the first visible work estimate. Its existing
20 epochs, 2,500 rows, and batch size 64 imply 14,400 optimizer calls if
all candidates finish. The separate Pareto script has 102 seed-candidate
trials and remains for P5.5b.

## Decision

Add a pure app estimator over the exact resolved synthetic candidate
configs. For each candidate and seed it counts `epochs * ceil(rows / batch)`
training updates and `epochs * rows` example exposures. The policy script
prints the bound before Torch or dataset construction and provides
`--estimate-only`. Its automatic launch ceiling is 1,000 planned updates;
a caller must explicitly set a sufficient
`--max-planned-training-updates` to launch the 18-candidate study. New
completed output records the estimate and launch ceiling.

The 1,000-update default allows a small candidate but prevents the full
14,400-update script from launching by an unqualified command. The limit
is a launch decision, independent of model performance. The candidate
list, seed, training settings, guard/validation split, and selection metric
stay fixed.

## Alternatives

- Estimate after constructing data: rejected because expensive resources
  would already be open.
- Guess elapsed time or memory from update counts: rejected because the
  current runner does not provide a calibrated conversion.
- Reduce candidates or epochs to fit the automatic ceiling: rejected
  because it would silently change the historical tuning protocol.

## Consequences

The no-argument policy script now refuses its large default launch and
explains the necessary explicit ceiling. The estimate is an upper bound
on training calls; early stopping can lower actual work. It excludes
validation, guard, inference, warmup, and resource use. Runtime update,
wall-time, replay, capacity, and memory stopping remain P5.5c/d; Pareto
preflight remains P5.5b. No scientific outcome was generated by this change.
