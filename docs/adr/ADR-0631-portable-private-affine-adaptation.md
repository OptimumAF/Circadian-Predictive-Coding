# ADR-0631: compose private affine adaptation from a fresh TRAIN stream

Status: accepted implementation decision; execution evidence is scoped separately.

Context: the normal first-party workflow learns ABC and plays known B/C. The
accepted private comparison and returning-A games require historical run files.
Their source parameters and original protocols already answer the fixed-task
learning/retention question; another retrospective capture increment adds little.

Decision: add an opt-in mode in the existing workflow and CLI. Use the actual
current-run six-fit TRAIN endpoint, original F collector/release validation,
existing private comparison and original native F/return-A binding. Add only an
optional outer boundary callback to the existing stream and explicit fresh-lineage
cost metadata. Default modes and fitting/evaluation math stay unchanged.

Why this: users can execute useful adaptation from birth without downloading
research files or trusting reconstructed parameters. A whole-workflow deadline
checks existing phase boundaries; it does not renew their original allowances.

Alternatives: bundling historical models keeps the archive dependency; creating a
new runner duplicates role/budget/receipt semantics; promoting the better private
arm would introduce selection and deployment scope unsupported by this protocol.

Consequences: both private models and all failed/negative outcomes remain visible.
TRAIN is frozen throughout private work. Ten total fits/252 row exposures include
repeated F or old TRAIN costs explicitly. Known fixed tasks do not establish
generalization, CPC benefit, matched computation or broad release qualification.
The existing normal-workflow inspector needs a separate future product extension
to display this schema; JSON is the current output. No independent review is
claimed under the current single-agent policy.
