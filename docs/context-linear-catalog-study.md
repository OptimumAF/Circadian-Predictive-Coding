# Train and freeze the owned LS catalog chooser

The existing finite catalog trainer can run from the ordinary workflow's current
owned least-squares (LS) checkpoint:

```text
python -B -m scripts.recurring_ticket_workflow_example --method linear_fit --context-return --separate-context-heads --catalog-study --output NEW.json
```

Output must be new. This mode excludes other adaptation and private-probe modes.
Existing commands keep their defaults. This command performs paid model work;
use an explicit local budget rather than treating it as an inspection command.

The source learns twelve ordinary TRAIN batches (72 row exposures). Its original
12-update/240-second/512-MiB budget is created before training and stays binding
throughout the study. Why this: six discarded trials and one application need a
longer source lifetime than a single trial. No live budget is renewed; the
existing 30-second source and probe defaults are unchanged.

The existing counterfactual trainer observes new-v1/mistakes then old-v1/clean.
Each receives the fixed wait, wake1, replay6-wake1 actions. The original objective,
six known TRAIN task readouts, replay bank, version/digest binding and fourteen
serving opportunities remain in force. Prior paid outcomes are validated before
more work. A lost delegated return makes aggregate work unknown; corrupted or
replaced preceding evidence closes future work.

Only six complete known trial rows permit fitting the scalar action chooser.
One frozen development application then uses the original source, guard,
sampler and actor. Private candidates never replace the served actor. All trial,
application, diagnostic, replay, source and worker costs remain paid. Final
evaluation and isolated fresh-task probes are unavailable to selection or fit.

The report retains trial outcomes, fit, application, controller state and native
training totals. It can demonstrate selection under this fixed objective on
known TRAIN templates. It cannot establish generalization, matched compute,
circadian advantage or release readiness. Waiting and negative task utility are
valid outcomes. See the [bounded execution report](reports/context-linear-catalog-study-20261029.md).
