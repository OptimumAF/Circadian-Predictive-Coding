## Purpose and boundaries

`python -m scripts.run_continuous_robot_learning` composes two existing APIs in
one process: fixed TRAIN A/B/A learning, then frozen TRAIN17 A inference with the
returned detached candidate. All four existing families are supported: `bp`
(default), `pc`, `neutral-cpc`, `active-cpc`. There is no new learner, optimization
recipe, orchestration framework, model serialization, promotion or corrective
training. Native inference performs no optimizer, latent or wake updates.

This is an explicit command that spends both training and simulator work. A
small prospective local protocol is required before comparative execution;
`--help` and fake-boundary tests do not grant native experiment authority. The
accepted lighting cohort is spent and its models were not archived. Reuse its
negative evidence rather than rerunning it merely to reconstruct models.

## Python use and reports

```python
from scripts.run_continuous_robot_learning import run_learning_rollout
report = run_learning_rollout(output, warm_train, new_train,
                             learner_family="neutral-cpc", phase_updates=8,
                             visual_observation=True)
```

`output` and `output.name + ".rollout.json"` in the same directory must both be
absent before fitting. Both are exclusive: old evidence is never overwritten.
The parent directory must exist. A concurrent creator may still cause native
output refusal after training was spent; that failure is retained. This is not
an atomic transaction spanning both files.

Combined JSON contains `training`, `rollout`, `rollout_attempted`,
`candidate_unchanged`, `rollout_output`, `complete` and an error when applicable.
The native trace is also written by the existing frozen-rollout API. Returned
training/native reports are saved before later handoff checks. Admission failures
before fitting raise and create no combined report. Failures after reserving the
combined file return `complete=False`, retain reports already returned and never
substitute a fallback model. The CLI prints the combined JSON and returns0 for
complete runtime behavior,1 for incomplete work; input errors use argparse.
Native exceptions may have spent work recorded in the native trace even if no
native report returned, so missing returned work must not be interpreted as zero.

The candidate must match the completed in-process runner's family, full policy,
specification, source identities, counters and final owner checks. It is not
loaded from arbitrary external report/model pairs; these metadata checks do not
authenticate third-party matrices. Exact native state admission includes full
parameters, momentum and coherent CPC configuration/wake. Public observers are
followed by native-owned validation to refuse late callback mutations or owner
class replacement. The same guard runs immediately before and after native work.
The original native exception and a secondary state-guard error are both retained.

Native output must agree on policy/source counters, TRAIN17/default A binding,
zero optimizer updates/no corrections, source/private frozen flags and exact
sampled joint telemetry. Task reward/success never gates completion: zero return
and observed joint violations are valid reported outcomes, not policy selection.
Joint telemetry samples reset and returned controls; it does not establish
continuous-time safety or all constraint compliance. No model is returned or
published by this composition.
