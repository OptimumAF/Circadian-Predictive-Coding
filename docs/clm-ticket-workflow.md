# CLM catalog learning to complete local ticket episodes

The separate [32-pass TRAIN-only qualification](reports/clm-train32-native-20261025.md)
fit all 12 known TRAIN rows, including legacy/password. It used a fresh 32-step
policy, 384 query exposures and no workflow rollouts. The CLI still defaults to 8;
this result does not establish generalization, retention or context return.

The [public-observation native case](reports/clm-public-native-20261025.md) completed
ordinary and stale tasks, with the dispatcher denying the revoked commit. TRAIN
fit after its eight passes improved4/12 to10/12; legacy/password remained incorrect.
That case is partial known-task learning, not continual-learning acceptance.

The earlier [original-recipe observation](reports/native-clm-ticket-workflow-20261025.md)
completed: unchanged heads solved 0/3 episodes; trained heads solved 1/3, recovering
from a stale parcel observation. Invoice failed for both and revocation was not
reached. This is limited known-task usefulness, not reliable adaptation or a
circadian advantage. Original costs, failed engineering gates and current query
variation are recorded in that report; no native retry is scheduled.

This driver connects the existing catalog learner, delayed TRAIN inbox, frozen
typed predictor binding and local workflow dispatcher. It fits all steps of a
ticket task, then observes complete bounded episodes, including stale-observation
recovery and commit-permission revocation. Wrong permitted workflows can commit
and count as failure. No host filesystem/network/tool handler is available.

```powershell
python -B -m scripts.run_clm_ticket_workflow --model-dir <prepared-model-dir> --head <prepared-head> --output <fresh-report.json>
```

Use the already prepared pinned offline [CLM assets/environment](clm-frozen-encoder.md).
The script installs/downloads nothing. Its software qualification grants no
pretrained experiment: freeze a separate finite native protocol before a run.
The output must be fresh; occupied output is refused before model loading.

Add `--reuse-action-features` to reuse the five public action embeddings already
computed during TRAIN extraction. This explicit option encodes only the current
query on each typed call; both head projections still run afresh. Defaults remain
uncached. No fitting, permission, episode or forward-call allowance changes.

## Optional TRAIN fit diagnostic

Add `--record-train-fit` (or `record_train_fit=True` in the Python entry points)
to record the original twelve TRAIN rows immediately before and after the fixed
eight updates. This option adds no encoder call or training update. It uses the
existing `predict_choices` port on the already-paid frozen features and all five
candidates, explicitly marked TRAIN. Default reports retain their original schema.

`train_fit` contains exactly two bounded readouts. Each stores its 12x5 returned
probabilities, target and selected IDs, correctness, concept and workflow phase.
`probability_margin` means target probability minus the largest OTHER candidate
probability; it is not a logit margin or calibrated confidence. Ties use the same
candidate-ID ordering as typed decisions. Per-phase aggregates report four rows,
correct count and mean probability margin for sealed, ready and staged states.
These are repeated known-TRAIN rows, not independent examples or task success.

The extra readout work is two predictions /24 query rows /10 candidate rows,
four head forwards /34 projected rows, staged head copies, full state captures,
feature checks and scalar reporting. Only those exact readonly counter changes
are admitted; weights, gradients, modes, optimizer/scheduler, source generation,
RNG and original feature values/owners must remain intact. The original eight
TRAIN receipts, clocks and budgets remain authoritative. A completed diagnostic's
container, point-record owners and values are checked before further work.

Each readout reports attempted/returned/validated/complete separately, native
work before/after, source-preservation status and `elapsed_seconds`. The timer
includes helper admission, feature copies, captures, native read and summary; it
excludes outer callback/prefix checks, output writing and the persistent feature
guard's initial copies. Overall case timing and observed copy counters remain
necessary for a full cost statement. Failed or corrupted reads stop further work;
`preserved_train_fit` retains the trusted prefix and observed failed-call costs.
It does not authorize restoring or renewing anything.

The [software qualification](../artifacts/runs/clm-train-fit-diagnostics-20261025/RESULTS.md)
has33distinct checks per platform, including actual tiny on/off full-state and
episode equivalence. The [native public-observation diagnosis](reports/clm-public-native-20261025.md)
now records partial TRAIN fit separately from task outcomes. The earlier original-
recipe observation predates this option; its spent allowance remains unchanged.
Freeze a distinct justified protocol and account for added readout/copy work
before any future pretrained study; these TRAIN numbers never select a probe,
promotion, stopping point, seed, dose or final-evaluation comparison.

## Fixed learning and inference

### Public-observation TRAIN option

`--public-observation-train` (Python: `public_observation_train=True`) explicitly
uses the live public request builder for the twelve teacher observations. The
original recipe remains the default, including its ` train` suffix. The new
recipe retains the checkout's existing live ` please` suffix and records
`observation_recipe: public_workflow_request_v1` with the distinct TRAIN group
`train-workflow-traces-public-observation-v1`.

This changes TRAIN text and its declared source group. Targets, consent, candidate
IDs/descriptions/order, twelve successful teacher transitions, six distinct state
strings, eleven encoder sequences, eight passes, clocks and budgets stay fixed.
The shared builder consumes the same public phase/concept/feedback/capabilities
as serving; teacher targets and private ticket IDs do not enter model text. The
existing teacher API also supports its original policy-version/context options.
No stale/failure outcome or final/probe label generates additional TRAIN rows.

The original text difference is real, but its causal role in the native invoice
failure is unknown. The [focused qualification](../artifacts/runs/clm-public-observation-train-20261025/RESULTS.md)
proves software alignment and tiny integration. The [separate native case](reports/clm-public-native-20261025.md)
now records2/3 raw task success plus expected dispatcher denial, with two TRAIN
errors remaining. Keep all old results; any future study requires a distinct
justified frozen protocol, not reconstruction/refitting of old unsaved heads.

### Reusing an observed unchanged control

`--learned-only` (Python: `learned_only=True`) retains the fixed training and
diagnostic sequence but observes only the three learned-head episodes: ordinary
invoice, stale parcel and commit-revoked invoice. It makes no unchanged-head
predictions. `episode_controls` explicitly lists learned as observed and unchanged
as unobserved; the summary contains only learned, so an omitted outcome is not
presented as zero success. The default still observes both owners in six episodes.

Use this option when an existing unchanged control has the same source, public
inputs and assumptions. Link that evidence separately and count its original
costs. The option neither imports a saved score nor authenticates comparability.
It is not a mechanism for selecting favorable scenarios after seeing results:
all three scenarios remain mandatory, and control selection is fixed at invocation.
It can combine with `--record-train-fit` and `--reuse-action-features`.

The same twelve [local workflow TRAIN demonstrations](local-ticket-workflow.md)
provide sealed→open, ready→current workflow, staged→commit targets for four
concepts. All five active tools are candidates, so candidates do not reveal the
right next step. Six unique TRAIN state strings and five action descriptions
encode once; the twelve rows then reference detached raw features.

Eight12-query/5-candidate catalog batches pass through the ordinary inbox, with
observations at ticks0,2,…14 and labels/updates at1,3,…15. Explicit training
consent covers the fixed passes. Report actual receipts,96query exposures,
40candidate-row exposures and480training logits. The objective is the existing
directional `clm_full_catalog_cross_entropy_v1`, not paired consolidation. Native
4096raw→512projection geometry and other native settings remain intact.

All fitting finishes before inference or task-effect evaluation. A frozen
unchanged predictor copies original heads; the learned binding copies the trained
catalog heads. They share one frozen encoder and own separate immutable head
storage. Head projections recompute for every actual typed request; no projection
cache is retained. One observed public binding snapshot is separately charged
from the sealed TRAIN work. No source restoration or update-budget renewal.

Each predictor acts in three episodes: ordinary invoice, stale-once parcel and
commit-revoked invoice, at most six predictions each. The existing dispatcher
checks current phase/revision/capabilities at effect time. The model sees only
the typed public observation and candidate descriptions. Labels/private goals
never enter prediction. Final/probe examples are not constructed or supplied.

Reports keep full paid observations, choices, transitions, local outcomes,
candidate costs and native work. Recovery requires actual successful completion
after a refusal; reopening followed by a wrong commitment is not success. The
unchanged and learned snapshots get the same ex-ante episode protocol; realized
steps/effects can differ and must not be described as matched computation.

## Ownership, failures and costs

Original loaded heads, trained owner, predictor copies, frozen encoder and caller
RNG stay separately guarded. Serving counters advance only around observed
returns. Retain one source snapshot and at most six bounded episode records.
A changed prior TRAIN/episode prefix stops work and retains its trusted scalar
copy separately from the corrupted report. A throwing prediction preserves paid
native attempts. An unreturned pending episode has unknown effects rather than
zero-imputed work. Trusted Python callbacks are not contained by this sandbox.

The encoder is born with one TRAIN forward plus at most36typed forwards, batches
of at most16sequences. Native/source guard/copy counters, training, head work,
tokenization, candidate scans, dispatches, effects and sampled RSS/wall time stay
separate. Copy-element counts are not total allocations/FLOPs; public inner bounds
are540seconds/22GiBsampledRSS, not a claim of feasible latency for every endpoint.
Any experiment must declare stricter relevant physical/time/storage bounds first.

## Optional raw action reuse

`FrozenActionFeatures(identity, candidates, features)` is an inference declaration
in `src/core/clm_action_features.py`, not a TRAIN batch or provenance certificate.
The concrete predictor and catalog binding accept it through `action_features=`.
Candidate IDs, descriptions and order must match exactly; the declared encoder
must match. The matrix must have2..64rows, the declared width, finite detached
CPUfloat32 values, contiguous layout, zero offset and exactly its logical backing
storage. Workflow supplies its fixed five already-encoded TRAIN action rows.

Each predictor owns one raw matrix copy and retains the original for guards.
At native4096width this is20,480values/81,920logical bytes per matrix. The two
workflow actors share the original and each own a copy. No query/head projection
cache or growing record chain. Lifetime is that exact frozen encoder/catalog;
there is no time TTL or automatic refresh. Changed original/owned storage, values
or metadata, a failed encoder guard, or uncertain prediction permanently stops
the cached predictor. A mismatched request catalog refuses before paid prediction.
Trusted Python ownership guards do not provide hostile-process containment.

Optional `action_feature_*` counters record copy attempts/returns/elements, read
attempts/returns/rows, guard attempts/returns and equality-validated values. The
last counts matrix positions compared, not every memory access or finite check.
Default work schemas stay unchanged. `action_feature_reuse` records workflow
source, finite size and lifetime; encoder/head work remains separately visible.
See [ADR-0554](adr/ADR-0554-frozen-raw-action-reuse.md). Native batch-shape numerical
parity and useful outcomes remain separate from literal software correctness.

## Structure and checks

The existing `fit_catalog_workflow(..., passes=8)` app helper accepts an explicit
integer count from 8 through 32. It requires a fresh native learner whose original
policy has that exact update allowance, twelve rows and zero restores. One
original budget, delayed-label inbox and logical clock cover the entire run.
Reusing a spent owner, replacing prior evidence, or changing its original limits
refuses before more work. Nondefault records include `requested_passes`; default
eight-pass records retain their schema. The complete workflow CLI still uses 8.

Why this: a 32-step OneCycle schedule must be born as a separate run; extending an
eight-step owner would renew its spent authority and change the experiment. This
bounded API enabled a separately frozen TRAIN fit qualification. Its known-row
fit supplies no evidence about new native task outcomes, retention or recovery.
The eight-pass legacy/password errors remain part of the scientific record.
See [issue #148](https://github.com/OptimumAF/Circadian-Predictive-Coding/issues/148)
for scoped literal correctness checks and resource evidence.
