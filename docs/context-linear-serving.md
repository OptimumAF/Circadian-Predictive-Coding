# Serving owned context LS policies

The existing recurring workflow can opt in to the same live serving, promotion
guard and rollback path using the contextual least-squares learner:

```powershell
$env:TEMP='D:\Dev\_Temp'; $env:TMP='D:\Dev\_Temp'
python -B -m scripts.recurring_ticket_workflow_example --method linear_fit --context-return --separate-context-heads --paired-serving joint --output artifacts/my-new-serving-result.json
```

Run from the physical D: checkout and use a new output path. This command trains
and serves; it is not a zero-work preview. Budget any future execution before
running it. The accepted engineering captures below need no repetition.

The original source workflow pays12 TRAIN fits/72 rows. Its live source guard
keeps the original budget, monotonic clock, sampler, source/actor checks and
owned report/receipt identities. Only the exact D9/six-class contextual LS
checkpoint12/72 with head histories8/48 and4/24 is accepted. It must have solved
the four declared source TRAIN tasks. Private/probe/final sources and historical
LS weight files are unavailable through this option. The original Perceptron
default and historical admission remain strict and unchanged.

The child uses the existing static paired TRAIN joint recipe and schedule:
four9row fits for new head/task pairings plus two6row old-return fits. These are
additional native fits, not free source initialization. The existing unchanged
guard can publish a detached whole candidate slot only after its explicit
new/old inner guards pass. Public task readouts are never fed into fitting or
the guard. The live worker reads one complete actor slot per request; source,
candidate and actor remain distinct. Existing rollback restores the whole
source slot with a new generation and original configuration/cache metadata.

`--paired-serving current` also selects the existing repeated-current recipe;
that mode has not received a full LS CLI execution in this increment. Its guard
may reject forgetting. No guard threshold, baseline, seed or metric is tuned.
Other private/catalog/feedback combinations remain unavailable for this LS path.

`ContextLinearServingPredictor.native_work` reports bounded aggregate outer
decisions, context projection/tokenization, selected-head affine/unfitted reads
and nominal affine terms. Each request still uses a fresh owned frozen readout.
Lost returns retain read costs and latch serving refusal. Owned LS fit failures
retain their `TrainingUpdateFailed` definition/work; unfinished fit time intervals
are unknown, not counted as measured overlap. Logical complete-record bytes
include fit evidence/policy/counters, while coefficient bytes alone do not.

[Executed evidence and limits](reports/context-linear-serving-20261029.md):
one full CLI joint integration per platform, six published known workflows
complete, exact source rollback,78worker requests/platform complete. This is
useful scoped serving behavior on TRAIN templates with known public context
cues. It is not a dynamic-retention comparison, unseen-task generalization,
an autonomous controller, CPC advantage or release qualification.
